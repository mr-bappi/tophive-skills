# Art Direction & Reference Intelligence — principles, not screenshot recipes

The local Design Lab contains a larger working library; a cloud-installed skill cannot silently access it. This portable reference distills reusable art-direction *questions*, with accompanying COMPOSITION-ATLAS.html topology diagrams. Refer to the atlas only as generative grammar; it is not a set of ready-made website themes.

## Study method (required for fresh brand builds)

1. Locate trustworthy **brief evidence**: verified assets, product interfaces, physical artifacts, content samples, expected reader/buyer action. If accessible, inspect references provided by the user and their licensing context.
2. Select 2–3 competing **conceptual references** based on what they solve, not celebrity visual trends. An internal/topology diagram may suffice when browsing is unavailable.
3. For each, extract the *principle*: reading path, density, negative-space tension, object scale, proof placement, type behavior, interaction trigger and responsive transformation.
4. Record one **anti-reference** for a tempting generic treatment not justified by this product.
5. Translate principles into an original, coherent direction. Do not duplicate another site's identity, assets or proprietary code.

## Eight original topology studies (see portable atlas)

| ID | Attention path | Useful when | Important risk |
|----|---------------|------------|----------------|
| T01 | Monumental type → marginal note → content | Distinct editorial thesis | Giant type without enough reading contrast |
| T02 | Immersive object → contextual annotation | Physical craft or observable object | Beautiful product photo but no buyer decision |
| T03 | Index rail → irregular catalog → detail | Deep library or issue archive | Dense navigation overwhelming mobile |
| T04 | Control → outcome → explanation | Interactive science/tool demos | Decorative controls that do not change content |
| T05 | Timeline → branching evidence | Incident or process investigation | Fake charts and unreadably tiny nodes |
| T06 | Paired alternatives → inspect differences | Evaluation / purchasing choice | Equally weighted items without criteria |
| T07 | Staggered scenes → progressive reveal | A narrative with evidence at each stage | Scroll hijack, empty full-height slides |
| T08 | Active workspace → supporting context | Actual operational applications | Marketing hero eating screen real estate |

These IDs are **not a classification shortcut by industry**. A magazine can need T03 more than T01; a security landing page can need T05 or T04. Each topology is a question about the product, not a look.

## Visual craft vocabulary

- **Type:** display geometry, distinctive but legible editorial punctuation, varying line length, precision label roles, optic alignment, reading measure and hierarchy; avoid reflexive bold sans + italic serif.
- **Image:** real product photography or owned illustration; crop intention, environmental context, texture/lighting and art-direction consistency. Unavailable visual assets require honest illustration, not imaginary proofs.
- **Grid:** edge tension, margins, overscanning, asymmetric weight, proportion, intentional overlap, reading path and breakpoint morphing.
- **Material:** paper, interface glass, structural metal, ink, canvas, natural surfaces are *metaphors* only where the product warrants them. Avoid decorative random gradients.
- **Motion:** animate state, causality, sequencing, spatial hierarchy and actual affordances. One coherent signature beats a dozen fade-ins.

## Originality and source rights

- Do not lift exact layout, copy, brand artwork or font files from references. Ask for rights before repackaging third-party assets.
- Do not claim that an inspiration URL was visually inspected if the agent did not inspect it.
- Do not invent testimonials, clients, integrations or runtime product screenshots.
- If external reference inspection is unavailable, state the limitation and use the bundled original atlas plus evidence from the brief.
- The atlas is original schematic HTML/CSS authored for study; all labels and shapes are placeholders, not production designs.

## Creative decision record

Before coding, keep a short internal record: source facts; chosen topology and why; rejected alternative and reason; visual signature; product-specific interaction; mobile treatment; risk. The final handoff can summarize this briefly. Do not replace user-requested BUILD work with pages of design analysis.
