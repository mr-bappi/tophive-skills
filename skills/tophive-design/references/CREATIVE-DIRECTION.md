# Creative direction engine — originality through product truth

Read for website BUILD/EXPLORE and *only* relevant aspects of expressive application design. For independent greenfield brands load `CREATIVE-DIVERSITY.md`; before visual signoff load `DISTINCTIVENESS-GATE.md`. This does not authorize rebranding an existing product. The direction must emerge from the actual product, not an imported generic aesthetic.

## Signature before surface

Write a private design brief: audience; product's unique job; emotional/functional perception; verified differentiation; one core metaphor; one visual signature; one authentic demonstration. Name a specific anti-reference: e.g. no unrelated gradients, random blobs, same-size three-card feature grid or made-up logos.

Define coherent roles for typography (display, section, content, utility), font metrics/wrapping, palette and token intent, grid/breakpoints, compositional rhythm, image use and motion. Derive from the product's existing design system when known. No universal mandatory 1240px container, serif headings, navy gradient or giant hero.

## Distinct directions in EXPLORE only

A real different option changes at least three: hierarchy/story, typography character, spatial composition, authentic demo format, color strategy, interaction metaphor. Recoloring one SaaS template three times is not differentiation. Explain tradeoffs and accessibility. In BUILD mode, select the best direction internally and implement; do not block execution on unnecessary approval.

## Coherent visual story, not recurring decoration

The visual system must carry a recognizable idea beyond logo or accent color. Give imagery, typography, navigation, proof and section rhythm **different but coherent jobs**: an image can establish place, show evidence, explain a process or invite exploration; it should not be reused everywhere as an interchangeable backdrop. Vary composition only when a new content question warrants it. Do not mechanically repeat serif + italic emphasis, tiny uppercase eyebrows, the same left-text/right-image split, sequential card grids or a dark-band interlude. Equally, do not force novelty where reading consistency or a locked brand requires repetition.

Inspect the entire page as an editorial/functional journey: where does the visitor start, what changes after each section, what can they actually inspect or do, and why would they continue? Prefer one clearly developed signature object or authentic proof system over a collection of disconnected visual flourishes. Match type size, image fidelity, crop and actual content density at mobile and desktop. If a source lacks suitable assets, change the representation honestly instead of recycling the same image into unrelated stories.

## Section design test

Every significant section answers a new user's question and therefore may deserve a new composition. Common narrative functions: what/for whom; core mechanism; authentic product proof; workflow; differentiation; trustworthy support; decision/CTA. Do **not** hardcode seven sections or fill with repetitive equally sized cards. Prefer real product screenshot, semantic diagram or deliberately labeled concept over decorative fake dashboards.

For original typography and motion decisions, read `TYPOGRAPHY-INTELLIGENCE.md` and `MOTION-INTELLIGENCE.md`. A fade-only website is not a motion signature. A different font name alone is not necessarily distinct typography.

## Type, color and motion craft

Use limited purposeful text sizes, correct weights/contrast, natural line breaks that survive 360px, consistent baselines and optical balance. Use color tokens in the target repo. Motion must communicate spatial/state relationships, remain optional/reduced-motion safe and never obscure reading. Preserve sufficient touch target spacing and readable code labels.

## Anti-generic audit

Check each output: could it be swapped to another product by changing logo and accent? If yes, improve the product proof and composition. Does repeated card language undermine information hierarchy? Are prominent numbers verified? Does mobile retain the intended identity without overflow or enormous gaps? If a section cannot justify itself, reduce or remove it.
