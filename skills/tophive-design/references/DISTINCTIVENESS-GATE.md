# Distinctiveness gate — finish review with evidence

Load for **new website BUILD**, significant creative redesign, and exploratory UI concepts. For existing brand work, prioritize fidelity and explicitly mark the novelty check **NOT APPLICABLE** when a locked system is intentionally reused.

## Two independent quality questions

**Product fidelity:** Does this interface express the verified product job with appropriate real/illustrative proof, useful actions and truthful data?
**Recognizable distinction:** Could the design be mistaken for an unrelated product merely re-labeled?

High fidelity without originality may yield a generic template. Novelty without fidelity is a decorative failure. Treat both as distinct review dimensions, not a single visual appeal score.

## Evidence-led self-review

Inspect desktop AND mobile captures when available. Check these axes:

| Axis | What counts as a meaningful difference? | What does NOT count? |
|---|---|---|
| Story | Different problem → proof → action priority | Renamed section headings |
| Composition | Different hero logic, geometry, reading path, navigation and content structure | Same layout with a new logo |
| Typography | Genuine type hierarchy/voice and wrapping tailored to brand/content | Italicizing one word |
| Palette/material | Brand-grounded surface, contrast and accent roles | Swapping sage for teal |
| Proof object | A real product-specific visualization or interaction | The same fake dashboard with new labels |
| Interaction | Distinct meaningful state journey or task demo | Decorative hover on identical cards |

### Heuristic only (never auto-certify with text matches)
- **Potential collision:** 4+ axes match a *verified, unrelated* previous output and no shared-brand rationale exists.
- **Repair recommendation:** revise at least 2 structural axes (story, composition, typography system, proof, interaction). No need to revise solely due to shared typography when actual brand tokens demand it.
- **Preservation rule:** for refined/reviewed existing UI, avoid unauthorized redesign; report identity sameness as acceptable or NOT APPLICABLE if deliberately mandated.
- **Truth:** Do not falsely claim the browser inspected a reference that the client cannot access.

## Creative outcome comparison (first-pass challenge)

Compare the chosen first render against the *benefits* of the strongest rejected internal candidate, not against an imagined screenshot. Ask whether a different reading path, evidence object, image treatment or typography role would materially improve the visitor's understanding and the brand's distinction. The answer may be **no**; do not force redesign or manufacture numerical self-scores. If **yes**, name the observed deficiency and repair a real structural choice before declaring completion. Keep existing approved brands intact, and never claim an independent A/B win from an agent's own critique.

## Repair with the smallest meaningful change

Fix the root of genericness, not by sprinkling artifacts: replace a filler card section with authentic product behavior, move actual proof above marketing claims, rethink the visual metaphor, use a different reading path, or adjust density/typography for the specific user's task. Retest accessibility, responsiveness, functionality and content after revising.

A self-scored PASS or static package test is not evidence of superior design. Run the external independent blind A/B benchmark from qa/blind-ab when evaluating a new version; no score is implied by merely adding these instructions.

## On delivery

Report whether a real cross-project comparison was possible and what evidence was inspected. **PASS** requires genuinely inspected relevant source/captures; **NOT TESTED** when previous outputs or rendered screenshots are unavailable; **NOT APPLICABLE** when existing locked brand rules require similarity. Never claim "100% original" or legal originality, and never treat an agent's unreviewed self-score as independent verification.

## External laboratory evaluation (not part of installed package)

The master Skill Lab compares multiple independently generated real artifacts across different product prompts, using screenshots plus structured human comparison. A scoring script does **not** generate designs or infer human judgment automatically. See external `qa/skill-evals/` if authorized local access exists.
