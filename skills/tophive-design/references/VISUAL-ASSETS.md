# Visual assets — truthful product imagery and deliberate composition

Assets should prove actual product behavior, not simply fill visual space.

## Preference order

1. Existing target repository assets or user-uploaded screenshots, with permission and verifiable product context.
2. Official product visuals or documentation, when accessible and rights allow.
3. A purpose-built semantic UI visualization derived strictly from verified behavior.
4. A clearly labeled illustrative placeholder when real media isn't available.

Never present generated dashboard charts, license statistics, testimonials, review counts, security badges or fabricated product screenshots as authentic data. A source URL establishes possible reference, not reuse license or permission to modify the source page.

## Image/layout workflow

Choose asset role per section: hero product artifact, feature detail screenshot, workflow explanation, trust evidence, avatar/icon, narrative illustration. Preserve aspect ratio, crop intention, safe-area, consistent resolution and responsive behavior. Define alt text for informative images and empty alt for decoration. Avoid many low-value images, watermarks or stock visuals detached from product truth.

If a user explicitly asks for a rendered illustration/image, use the available image-generation workflow when authorized; do not assume this skill grants image editing tools. If image generation or retrieval is unavailable, report limitation and use a semantic placeholder without implying tool access.

## Verification

Inspect actual image loading, CLS/layout space, alt semantics, overlap at 360/390 and 1440/1920, color contrast over photography, text clipping on mobile. Do not ship broken image paths or hotlinked unstable assets.
